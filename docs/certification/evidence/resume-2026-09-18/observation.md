# Ordinary continuation with a read-only resume brief

Two separate Cursor IDE conversations used the same built core and payload.
Immediately before each submitted prompt, the native UI showed GPT-5.6 Luna,
Medium reasoning, and Fast off. Each prompt was entered intact as one message;
there was no corrective follow-up or repeated task attempt.

## Saving conversation

The assistant reviewed the synthetic brief and wrote a preliminary readiness
note. It changed the existing goal's next action from confirming attendance to
confirming the venue and duration before drafting the handout. All other goal
fields remained intact. It saved a sourced Fact for the 14-person limit,
registered the original brief, wrote a grounded card, and took a managed snapshot.
The note retained the unknown venue and duration instead of filling them in.

The [saved outputs](results/saving/project/readiness-note.md) and corresponding
[goal](results/saving/Goals/prepare-lantern-workshop.md),
[Fact](results/saving/Memory/Facts/lantern-workshop-attendance-limit.md), and
Library records are exact copies. Their relative source links resolve within
this evidence tree. Complete before/after hashes also cover the synthetic
recovery store and isolated Library cache.

## Fresh no-save conversation

The ordinary request said to pick up the work using its saved context. It did
not name the resume command or supply the answers. The native command details
showed `EXECUTABLE resume WORKAREA`. The assistant had opened the independently
bound project and resolved its linked work area; it used that direct work-area
argument for the command. This does not separately prove the native CLI's bound
project argument route.

The observed brief was partial: one active goal showed the updated next action,
one registered source was available, and the latest snapshot was unavailable.
Git was deliberately removed only from the product process PATH by a declared
launcher. The assistant continued, inspected the existing no-save task, recalled
current Memory, and read the relevant project sources. Source availability was
not treated as an index, cache, or freshness attestation.

The resulting [facilitator handout](results/no-save/project/facilitator-handout.md)
cites the brief and readiness note, preserves the 14-person limit and printed
materials requirement, and leaves the venue, duration, and detailed exercise
instructions unresolved. Its generic session outline is a preliminary scaffold.
It does not use the outdated venue proposal or unrelated rehearsal context.

The [complete tree comparison](hashes/nosave-delta.json) proves that all 132
baseline files stayed byte-for-byte unchanged and no directories changed. The
only added file was the requested project handout. The baseline includes the
pre-created no-save task, goals, Memory, registrations/cards, recovery state,
project Git files, and the isolated cache. No human reminder was needed.

## Limits

This is one synthetic task pair on one macOS app configuration. It is not broad
support certification, default installer evidence, proof of provider retention,
or a complete operating-system write trace. The direct work-area command,
declared cache location and simulated Git absence remain part of its scope.
Other apps and native Windows conversations were not exercised. The core's
Windows reparse and binding cases require their separate CI results.
