## Objective

"One canon, many renders" becomes machinery instead of discipline. This PR
lands `apparatus render <workspace>`, which regenerates every app shim
(`CLAUDE.md`, `.cursor/rules/apparatus.mdc`, `.github/copilot-instructions.md`)
from the `AGENTS.md` canon at the workspace root; extends `check` with
canon/shim drift detection so a stale or hand-edited shim is a finding; and
replaces the PR-07 hand-built shims in the starter payload with rendered
output committed to the repository, pinned by a golden fixture. Shims become
what ADR-0003 says they are: generated artifacts, never hand-edited, with the
shim set extensible as data — adding a shim type is a template plus a registry
row, not new architecture.

## Acceptance criteria

1. `apparatus render <workspace>` writes every registered shim from the
   workspace's own `AGENTS.md`, creating parent directories as needed,
   printing one plain-language line per target (written or unchanged), exit
   0. A workspace without `AGENTS.md` is exit 2 with an actionable message.
2. Rendering is deterministic: same canon in, byte-identical shims out — no
   timestamps, no environment-dependent content.
3. Every rendered shim begins with a generated-file header comment stating it
   is generated by `apparatus render`, must not be edited by hand, that
   `AGENTS.md` is the file to edit — and carrying the SHA-256 digest of the
   canon it was rendered from, so editing canon makes every shim detectably
   stale.
4. Shim content per ADR-0003: each shim is a thin pointer directing its app
   to read and follow the workspace `AGENTS.md`; the Cursor shim carries the
   frontmatter its rules format requires (mirror what PR-07 shipped). Shims
   restate no canon content beyond the pointer.
5. The registry is the only place shims are enumerated: `render`, the drift
   check, and tests all iterate it. A unit test proves extensibility by
   injecting a synthetic registry entry and observing render and drift
   detection honor it with no other change.
6. `check` gains drift findings with stable codes: `shim-drift` (on-disk shim
   differs from an in-memory re-render, including a stale canon digest) and
   `shim-missing` (registered shim absent). Each finding's fix hint says to
   run `apparatus render`. Workspaces predating shims still get findings —
   missing is a finding, not a skip.
7. `render` after canon edits clears all drift findings; a test does the full
   loop (render → check clean → edit canon → check drifts → render → check
   clean).
8. Payload shims are the rendered output of the payload's own `AGENTS.md`,
   regenerated and committed. If PR-07's shipped shim paths differ from the
   registry's targets (e.g. the Cursor rule filename), standardize on the
   registry's paths and update `conformance/golden/payload-manifest.txt`
   deliberately in this PR, stating the rename in the PR description.
9. Stdlib only: `hashlib`, `importlib.resources`, `string.Template` or
   equivalent — no templating-engine dependency for three pointer files.
10. `uv run pytest` is green.

## Conformance and tests

- `conformance/golden/shims/` pins the exact rendered bytes of the three
  payload shims. `conformance/test_render.py` asserts:
  - rendering the payload's `AGENTS.md` in a temp copy reproduces the golden
    bytes exactly;
  - the shims committed under `starter/payload/` are byte-identical to the
    goldens (so payload and goldens cannot drift apart);
  - every registry target path appears in the golden payload manifest.
- These goldens change only when canon or templates change, deliberately, in
  the same PR as the cause — never loosened to silence a failure.
- `packages/apparatus-core/tests/test_render.py` covers determinism, the
  generated header and digest, exit codes, the synthetic-registry
  extensibility test, and the render/check drift loop from criterion 7.

## Out of scope

- Regenerating this repository's own root `CLAUDE.md` contributor shim — the
  repo dogfoods the pattern (ADR-0003 §5) but wiring repo-root rendering is
  a separate cleanup; do not touch files outside the listed deliverables.
- New shim types beyond the three PR-07 established; the registry makes them
  cheap later.
- Rendering `Welcome.md` or any profile-dependent content (PR-17).
- Watching for changes, editor integration, or auto-render hooks; `render`
  runs only when invoked.
- Any change to record schemas or the check behaviors PR-09 landed, beyond
  adding the drift pass.
