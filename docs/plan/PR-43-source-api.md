# PR-43 source helper API

`apparatus_core.library.sources` owns only selection records and safe reads. It does not extract, index, emit receipts, or copy an original.

- `normalize_source(path)` validates an exact portable work-area-relative spelling. `source_key(path)` returns its full SHA-256; `registration_path(path)` returns `System/library/sources/KEY.yaml`.
- `parse_registration(content, relative_record_path)` validates the closed YAML schema and exact filename, independently of whether the referenced original still exists. Recovery may call it without reading originals. Implicit Library files cannot have registration records.
- `Source(source_path, kind)` is immutable. Kind is `registered` or `library`; it must agree with the path. `.key` is the path hash. `.cache_relative` is an **extensionless string**: `references/KEY` or the existing `extractions/<Library-relative-path>`. Callers append `.json` and `.txt`.
- `with Catalog(workspace) as catalog` validates and retains the complete registered inventory. `.sources` is a sorted tuple of registered descriptors. Combine it with the existing bounded Library walk. `.source(path)` resolves only a registered path or an implicit `Library/` file; it does not claim the source is readable.
- `catalog.validate()` rechecks exact root/parent/record identity, bytes, and the whole record-name set. Missing catalog directory preimages are also retained: a newly appearing catalog invalidates the earlier empty inventory. Unknown entries, malformed records, portable collisions, and replaced parents fail the operation.
- Restore alone uses `Catalog(workspace, transaction_compatible=True)` while its original file and created-directory proofs remain retained. Compatible validation aliases share the required native transaction access; inventory, identity and exact-byte validation still apply. Ordinary source and catalog readers keep their default mode.
- During replacement, restore supplies `temporary_files` with exact unfinished transaction backup basenames and expected `(content, identity)` pairs. Catalog validates and retains those temporary proofs as inventory only; there is no prefix exemption and no temporary source registration. Ordinary readers reject them.
- Implicit `Library/` descriptors preserve safe native filename spelling, including decomposed Unicode and legal platform-specific names. This compatibility does not relax normalized portable spelling for new project registrations or allow traversal, links, control paths or credential-bearing source paths.
- `with catalog.read(source, rules) as reader` applies supplied valid ignore rules to the **full original path before content reads**, opens only that source through retained safe parents, and exposes `.content`, `.sha256`, and `.size_bytes`. `reader.validate()` rechecks its exact source and catalog. Keep both contexts open and call final validation before accepting extraction/retrieval results. `.close()` is idempotent. Omitting `rules` leaves ignore policy with the caller; all ingest/retrieval integration must supply its rules.
- `SourceUnavailable.reason` is `missing`, `unavailable`, `unsafe`, or `ignored`. Messages are bounded repair guidance without raw operating-system errors. `SourceError` covers untrusted catalogs and invalid selections; it fails the whole catalog rather than treating it as empty.
- `register_source(workspace, path, task_id=None, requested=False)` and `unregister_source(...)` return `RegistrationResult(source, changed, implicit)`. Both enforce existing Library retention authority first. Add checks feature state, ignores, and the selected original, then publishes only its record with exact-owner compensation. Exact duplicate add is a validated no-op. In-Library add/remove is implicit and never changes the original or creates a record. Remove does not need the original to be present and remains usable with indexing off. Callers perform selected extraction separately after a successful add and report registration/extraction outcomes separately.
- `list_sources(workspace)` returns a tuple of `SourceStatus(source, status)` with `.source_path` convenience access. Status is `available`, `missing`, `unavailable`, `unsafe`, or `ignored`. This reads registration/control metadata and source availability metadata only, never source contents or caches. Available means a regular named file was present, not that extraction succeeded or a content read is guaranteed to succeed.

No source/citation proof promises that mutable files stay unchanged after its final boundary. No-save requires the invocation-scoped explicit Library exception for add/remove; listing never creates durable state. A source move remains an unavailable old path until explicitly added/removed. Rollback touches exact invocation-owned files and empty created directories only, preserving competing writers.
