# PR-43 — Register selected originals as Library sources

Implementation contract on `pr-43-library-references`, grounded in ADR-0006, the R8 rework sequence and the current PR39 Library implementation. Final integration requires PR-39 and the patched dependency in PR-42; integrate intervening PR-40/41 changes before delivery. R9 cards and completion offers remain separate. This slice adds ordinary work-area-relative references to selected project files; it never copies/moves originals, creates symlinks, searches drives for replacements, or indexes unselected sibling projects.

## Current implementation facts

- `cache.py:12` uses the first twelve SHA-256 hex characters of the resolved absolute work-area path for the machine-local cache under `APPARATUS_HOME/library/`. This is not the enrollment UUID. Moving the whole work area chooses a different cache; registration must survive without relying on that cache identity.
- `library/ingest.py:53` opens `Library/`; `_library_entries` at 212 recursively lists only that tree with ignore/link checks. `_read_source` at 245 reads source bytes through the Library descriptor on POSIX and the retained workspace anchor on Windows. Registered project sources must instead resolve through retained, no-follow work-area parents; simply joining an arbitrary new path onto the old traversal is insufficient.
- Ingest stores `extractions/<Library-relative-path>.json` and `.txt`. Metadata has exactly source_path, source_sha256, size_bytes, extractor, extractor_version, status, error, character_count and timestamp. Source identity is currently `Library/<relative-path>`. Hash plus extractor version controls incremental extraction; valid terminal no_text/unsupported/error records have no text file. `_valid_record` at 449 already accepts a full source path parameter.
- `_remove_deleted` at 275 prunes pairs by the current scan's seen paths. It must not be reused over registered entries without a complete, validated selected-source inventory. Source read failure can leave old cache evidence today; R8 must prevent that old evidence from being cited as current.
- `library/index.py:727` has an FTS table with source_path/text and an indexed_sources table keyed by source_path with source_sha256, extractor_version and indexed_at. `_refresh_connection` at 91 synchronizes those keys; this SQL shape already accommodates project-relative citations.
- `_record_paths` at 953, `_extracted_sources` at 741 and `_is_extracted_record` at 796 derive identity and ignore matching by prepending `Library/` to extraction-relative paths. These are the main coupling points to remove. Current retrieval checks cached metadata/text but does not rehash the original before returning hits.
- `index.retrieve` at 391 is the shared search/recall entry. Saving tasks refresh persistent SQLite; no-save uses existing extractions and a fresh in-memory SQLite database with cache creation disabled. Explicit requested rebuild is a separate Library write exception. Preserve this boundary and existing safe database publication/locking.
- `commands/library.py:24` exposes ingest and search; ingest has `--requested`, search has `--rebuild`/`--requested`. `recall.py:96` uses the same retrieval path and emits source/snippet/score evidence; only saving tasks write its credential-redacted question/source receipt. Ingest writes the existing library-ingest event and flagged counts. Receipt binding must continue through the existing frozen task context.
- Library behavior is presently described across PR14–16 plans, workspace/ignore/retention specs and code; there is no standalone current Library registration schema/spec. Add one concise normative Library-source spec rather than treating historical plans as a new API contract.

## Durable source selection

Keep ordinary files already inside `Library/` implicitly selected, preserving current ingest behavior. For project originals, use one readable registration record per exact path under `System/library/sources/KEY.yaml`. A small closed schema contains only `schema: apparatus/library-source@v0` and `source: project/path/report.md`. Derive KEY deterministically from the normalized full work-area-relative source path; use the full SHA-256 hex digest and validate filename agreement. Do not use a content hash as the durable identity: editing an original does not create a second registration. Do not store machine-specific absolute paths, extracted text, summaries, timestamps or task prose in this record.

Accept normalized portable relative paths inside the selected work area. Reject absolute paths, traversal, ambiguous separators/control characters, link/reparse components, nonregular endpoints and portable case/Unicode collisions. Reject internal state/control paths: System, Memory, Goals and legacy Decisions roots, and .git/.apparatus/.agents/.claude/.cursor/.github components at any depth. Resolve a selected path relative to the work area even when the command is invoked from a bound project; state this in CLI help. Do not infer a different project/work area or follow a second binding discovery.

Apply existing ignore rules to the original workspace-relative path before reading content. An ignored source cannot become indexed merely through explicit registration. Report the blocking rule and existing repair route; do not toggle a feature or rewrite ignore rules. Existing files inside Library are already selected and do not acquire duplicate registrations. Unknown files elsewhere remain unselected regardless of similar names or matching bytes. Duplicate exact registration is a no-op; conflicting or malformed records fail before mutation. Validate the entire catalog before trusting it for source selection. A credential-bearing path must be rejected before durable storage; redacting a path into a different target is unsafe.

## Minimal commands and transaction boundary

Add three actions under the existing library verb:

- `library add WORKSPACE RELATIVE_PATH [--requested]`: validate and persist the selected reference, then attempt extraction of only that source. It must never trigger a whole-work-area scan or silently ingest all other registered sources. Return separate registration and extraction outcomes. If extraction is unsupported, empty, unavailable or fails, keep the valid registration for repair but do not claim the file is searchable. If registration publication itself fails, compensate its exact owned files/necessary receipt artifacts and preserve competitors.
- `library list WORKSPACE`: read-only listing of registered paths and bounded current availability/ignore state; no extraction, indexing, repair, cache creation or routine receipt. Distinguish registration from successful extraction.
- `library remove WORKSPACE RELATIVE_PATH [--requested]`: remove only the exact registration through identity/byte-bound ownership. Never delete, move or rewrite the original. Removal makes any cached registered evidence immediately ineligible; cache cleanup may occur during a later permitted ingest. It is not secure erasure of previous caches/backups. Implicit in-Library selection still uses the existing file/ignore behavior; this command does not delete an in-Library original.

This is source registration, not a relocation engine. If the original moves, list/ingest/retrieval report the old path missing; the user explicitly adds its new relative path and removes the obsolete registration. Do not search by basename or hash. Moving the whole work area keeps relative registrations valid but may require cache rebuild. An unavailable mount inside the work area produces unavailable coverage, not automatic deregistration or a claim of no matching evidence.

Both writes require the existing `operation`/`require_library_write` check before reading selected content, catalog mutation, cache creation or new content-bearing receipts. A no-save task permits them only through the explicit invocation-scoped Library exception; no snapshot exception or earlier request grants general Library authority. An explicit add exception covers the selected registration/extraction only. It grants no Memory, cards, learned Skills, activity capture or automatic snapshot. Feature-off remains off; add must report it without enabling indexing or publishing registration. Read/list and remove remain usable under their applicable retention controls. Reuse native authorization and credential handling; add no review gate or receipt event solely for registration.

## Shared source descriptors and derived cache

Add a small Library-source helper used by ingest and retrieval. It produces the exact workspace-relative citation path, source kind, retained safe reader and deterministic cache pair location. Combine the existing bounded Library walk with only validated registered paths; never recursively walk project folders.

Preserve legacy `extractions/` cache paths and metadata for in-Library files. Store registered pairs in a separate sibling cache namespace, for example `references/KEY.{json,txt}`, using the same metadata fields with the actual project-relative source_path. This avoids collisions and a forced rewrite of every existing cache. Generalize the index's record enumeration and validators to consume the descriptor's full source identity instead of inventing `Library/` prefixes. Validate registered cache entries against the live catalog, not against a cached source_path alone. Removing/ignoring a registration must filter it before any hit is emitted, including during no-save retrieval.

Keep the existing SQL schema, lexical scoring, extractors and supported formats. Refresh/rebuild receives a unified map keyed by exact source path. Only authorized writes may prune stale caches or update persistent SQLite; cache deletion/rebuild never deletes registration. Corrupt cache pairs cannot masquerade as unsupported/empty sources. Preserve private cache modes, no-follow protections, retained publication proofs and Windows lock behavior.

## Freshness and truthful evidence

Before using cached evidence, validate the currently selected original through retained parents and compare its bytes/hash with the extraction record, using the same rule for Library and registered sources. Recheck the relevant source/catalog proofs before accepting results. Same-size/same-mtime edits must not bypass this check. This establishes evidence for the bytes checked at the operation boundary, not a promise that a mutable file can never change afterward.

Changed, missing, unreadable, ignored or unsafe sources contribute no stale snippets. Search must not silently extract new bytes while answering a no-save query. A permitted ingest refreshes changed sources; retrieval otherwise reports that refresh is needed. A healthy source may still supply grounded evidence while another is unavailable, but coverage must be explicitly partial.

Introduce one small shared coverage result for search/recall: complete or partial, plus affected workspace-relative paths and bounded reasons. Keep existing hit fields and scores. Extend the recall envelope deliberately with this coverage information, and update human rendering and conformance together. No-hit with partial coverage is not an ordinary complete-library abstention: explain unavailable sources instead of stating only “Not in your Library.” Missing/corrupt extraction infrastructure remains unavailable, not an empty Library. Valid no_text/unsupported/error outcomes remain distinct from corruption and from a successful full-text extraction.

Do not copy source snippets into routine ingest diagnostics or registration metadata. Keep current redaction/source-as-data behavior and task-aware recall receipts. Metadata-only required evidence in an explicitly requested no-save operation must use the existing receipt path; never persist raw task queries or source text as an incidental log.

## Recovery, migration and acceptance

Add exact schema-valid registration records to managed recovery membership and historical validation; their source paths describe references, not files to restore. Snapshot/backup includes registration metadata, never project originals or extraction caches. Preserve later registration additions when restoring older snapshots, using existing per-file restore semantics. An old snapshot may revive an earlier registration; report the historical state honestly. R9 cards are absent from this cut.

Existing unregistered work areas and their Library caches keep working. No migration of original files is needed. Preserve profile and task controls, user rules, custom native Skills and dirty root/project Git state. Integrate the existing selected-work-area routing and current platform fixes; avoid new filesystem/SQLite frameworks.
