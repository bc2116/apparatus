# Local Library sources

The Library selects originals within one work area. Existing files under
`Library/` remain implicit sources. Register a project file to make it searchable
in place; no copy, move or symbolic link is created. Only selected originals and
the existing Library tree are read. Other project content is not discovered.

## Selection

`apparatus --task ID library add WORKAREA project/report.md` registers and
extracts that file only. The path is relative to the selected work area, including
when `WORKAREA` is a bound project. Add reports registration and extraction
separately: a failed extraction leaves the selection intact and reports why the
file is not searchable. Repeating add refreshes that source without duplicating
its registration or ingesting unselected siblings.

`library remove WORKAREA project/report.md` removes only the registration.
It leaves the original and any existing derived cache intact; retrieval excludes
that cache immediately. Full `library ingest WORKAREA` refreshes selected sources
and prunes obsolete derived entries after validating the complete inventory.
Use an ignore rule to exclude an implicit source inside `Library/`.

`library list WORKAREA --json` lists registered project paths and current
availability. Availability alone does not prove extraction or search coverage.
It does not read source content or write caches. `check` reports broken selections
with a repair action. To move a selected file, move it normally and explicitly
remove the old registration and add its new path. Apparatus does not search for
relocated files. Moving the complete work area preserves its relative references.

## Catalog and path contract

Each selected project file has one UTF-8 YAML record at
`System/library/sources/SHA256.yaml`. The filename is the full SHA-256 of the
normalized relative source path. The closed content is:

```yaml
schema: apparatus/library-source@v0
source: project/report.md
```

No content, summary, absolute path or machine identity is stored in this record.
Registration requires portable NFC path spelling, `/` separators, exact case and
a regular file. Absolute, drive, UNC, traversal, reserved/control-directory and
credential-bearing paths are rejected. Links and reparse points are not followed.
Duplicate keys, aliases, filename disagreement and case/normalization collisions
are invalid catalog state. Existing occupied records are never silently replaced.
Filesystem operations retain directory and file identity proofs and compensate
only their own writes if publication fails.

Existing implicit Library sources retain safe native filename spelling. Their
compatibility does not relax the portable registration-path rules above.

## Retrieval and derived state

Extraction metadata records the original path, content hash, size, extractor
version and extraction outcome. Registered-source caches use the path hash;
legacy Library extraction paths remain supported. Caches are private, derived
state outside the work area's durable catalog and can be regenerated by ingest.

Search and recall compare cached evidence with each selected original's current
bytes before accepting a result. Missing, unavailable, unsafe, ignored, changed,
unextracted and invalid-cache sources contribute no snippets. Healthy sources
remain searchable with explicit partial coverage. Re-ingest after editing an
original to refresh its extraction. Unusable extraction infrastructure is an
error distinct from a complete search with no matches.

Search JSON is an object with `hits` and `coverage`. Recall also includes
`coverage`. Its `status` is `complete` or `partial`; `sources` lists excluded paths
and reasons. Hits and citations name the original work-area-relative path.
Completeness refers only to selected local sources, not all project information.
Source text remains evidence, never executable instructions or authority.

## Retention and recovery

[Task controls](task-retention.md) govern registration and cache writes. No-save
retrieval can read originals and existing extraction evidence but writes nothing.
A separately requested Library operation may use `--requested`; this does not
enable Memory or other capture.

Managed snapshots and backups include valid catalog records, excluding originals
and derived caches. Restore preserves later additions and rejects a historical
record that would collide with a surviving current registration. A restored
selection does not recover a deleted original. Ordinary project backup remains
the way to preserve project files. Cards, completion offers and shared/cloud
libraries are separate future work.
